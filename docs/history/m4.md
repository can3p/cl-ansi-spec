# M4 — Patch tooling (done 2026-11-27)

Archived from `docs/plan/m4.md`. History only: the current rules live in
`patches/README.md`, `docs/architecture.md` ("Sources") and
`docs/tex-fidelity.md` ("Jobs").

Ran beside M3, in its waves A and B (`docs/plan/m3.md`), as two sessions:
4.1 alone, then 4.2 → 4.3 → 4.4 in one session (two pull requests, the
second stacked on the first).

## What was built

- **Unified diffs** (`cl-ansi-spec/patch`, `src/patch/`): a patch file's
  header, file pairs and hunks read strictly; applied to a file's lines
  with exact context at the stated lines, in pristine coordinates, with a
  condition for every failure.
- **The patch set** (`src/patch/set.lisp`): `patches/*.patch` loaded in
  name order and checked (names, distinct numbers, non-empty headers,
  each patch applies alone to the pristine tree, no two patches' hunks
  overlap or touch); `applied-patches` (name, SHA-256) for the manifest;
  `make patched`.
- **The patched tree behind the resolver**: the hook `*source-overlay*`
  in `src/source.lisp`, consulted by `open-line-source` for spec-tree
  files only, installed by the patch package, so `tex` does not depend
  on `patch`.  Every job reads the patched text under the file's own
  name.
- **Three patches**: 0001 restores the syntax-type table's abbreviations
  (concept-syntax.tex:272-278), so chap-2 has no TeX errors; 0002 drops a
  row break inside a `\curly` group (dict-iteration.tex:623-624); 0003
  adds the missing `\rparen` (concept-bvl.tex:1187).  The pins of
  `tests/semantic/spec-jobs.lisp` went with them; snapshots changed
  (chap-2 +464 events, chap-3 +3, chap-6 -21).

## What turned out wrong

- Applying patches in sequence with their own line numbers would let one
  patch shift another's (the whole-milestone critic): hunks are counted in
  the pristine file and merged into one edit set per file.
- 0001 made `\w \n \c \C \SE \ME` defined, so the vocabulary test asked
  for them to be classified: the step had to change
  `src/semantic/vocabulary.sexp`, a file of another phase.  Patches can
  reach the vocabulary; the step that writes one checks `make test` for
  it.
- Merging the parallel pull requests by "accept both" broke
  `cl-ansi-spec.asd` twice (a closing paren too many, a component twice):
  now a rule in `docs/process.md` ("Parallel waves").

## Left out on purpose

- Fuzz and offsets: a patch either applies exactly or is an error.
- Mapping patched lines back to pristine ones in spans: the manifest
  lists the patches, so the pristine tree and the patches reproduce every
  span; line counts are kept where possible.

## Options weighed

- A patched copy on disk versus an overlay in memory: the overlay, so
  jobs never depend on a build step; `make patched` writes a copy for
  reading only.
- Moving the patch package before `tex` versus a hook in the source
  package: the hook (4.2's critic), keeping one-way dependencies.
