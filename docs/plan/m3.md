# M3 — Semantic document model

Planned 2026-11-27.  Whole-milestone `plan-critic`: 2026-11-27 (findings
folded in below, see "Critic").  Runs in parallel waves
(`docs/process.md`, "Parallel waves"); M4 (`docs/plan/m4.md`) runs beside
it.

Goal (`docs/architecture.md`, `docs/model.md`, `docs/exports.md`): the
event streams of every chapter job become one documented, validated,
exported model of the standard, with every reference resolved or
reported.

## Decisions taken at planning

Each is a rule the steps implement; the step that implements it moves it
into the topic doc it names.

- **Section numbers** are counted by the builder per level from the
  section marks (`:section`, `:dictionary`, `:subsection` …), restarted
  under each parent, the chapter number taken from `\beginchapter`'s first
  argument.  They are *checked*, not guessed: `\DefineSection`
  (setup-aux.tex:1107) `\xdef`s its `\write`, so the `:write` event after
  each of the 278 `\DefineSection` marks already holds TeX's own number
  ("`!label Section 1.9.2`", `\ThisSection` set by `\toc`,
  setup-aux.tex:440).  A mismatch fails the build.  (Model, `docs/model.md`.)
- **Figure numbers** come from the caption text, which starts with
  `\chapno--\the\capno.` (`\caption`, setup-aux.tex:706, 737), checked
  against the `:write` of `\DefineFigure` (setup-aux.tex:1097) where there
  is one (24).
- **Ids** as `docs/exports.md` says: chapter label, `\DefineSection`
  label, first entry name (`<name>/<ftype>` on collision), glossary term.
  A section without a `\DefineSection` gets `<parent-id>/<n>`: its id is
  stable because its parent's is, and it is never a link target from the
  sources.  Figures: their `\DefineFigure` label, else `<chapter-id>/fig-<n>`.
- **Entry kinds** are an enum built from the `\ftype` texts (20 distinct;
  367 "Function" … 1 "Special Form"), kebab-cased.  Case variants
  (`macro`, `function`) and obsolete names are source errors: fixed by
  patches (M4), never by a normalisation table in code.
- **Fonts and text.** Inside a vocabulary entry the entry gives the
  meaning; outside, `{\tt …}` → `:code`, an italic → `:emphasis`, a bold →
  `:strong` (`docs/vocabulary.md`, "Choosing entries").  The builder
  applies the TeX font's ligatures and character codes that change the
  *text* (cmr `--` en dash, `---` em dash, ` `` ` and `''` quotes, `!``
  and `?``; none in cmtt), discretionaries become their no-break text,
  `\accent` a precomposed character.  Text is Unicode.
- **Math** is kept as a small tree of its own (`:math`: rows of
  characters with a class, sub/superscripts, fractions), characters mapped
  to Unicode by font family (cmmi, cmsy, cmex, cmr tables); nothing
  typeset.
- **Unresolved reference caused by a source typo** → a patch (M4), not
  an exception in code.  Every other unresolved reference is listed in
  the report with a reason, and the whole-spec test pins that list.
- **Fixtures** are real lines: tests build the model of a job's line
  range (`build-fixture`, 3.3), like `make events`, so every builder step
  tests against the sources without running the whole spec.

## Parallel waves

A wave's steps start from the same `main` and touch disjoint files (each
step's *Owns*).  Shared files follow the merge rules of `docs/process.md`.
A step may start when the steps in its *After* are merged.  M4's steps
are listed where they fit.

| Wave | Steps (model) | Gate to the next wave |
|------|---------------|-----------------------|
| A | 3.0 → 3.1 (opus, one session); 3.U1 (sonnet); 3.U2 (haiku); 4.1 (sonnet) | 3.1 merged |
| B | 3.2 (opus); 3.3 (opus), then 3.12 (sonnet); 3.4 (sonnet); 3.5 (haiku); 3.6 (sonnet); 4.2 → 4.3 → 4.4 (sonnet, one session) | 3.2, 3.3, 3.12, 4.3, 4.4 merged |
| C | 3.7 … 3.11, 3.13 … 3.15m (sonnet, up to nine sessions) | all of C merged |
| D | 3.16 (opus, alone: it touches every builder file), then 3.16p (sonnet) | 3.16, 3.16p merged |
| E | 3.17, 3.18 (sonnet); 3.19 (opus) | all of E merged |
| F | 3.20 (sonnet); 3.21 (haiku); 3.22 (sonnet) | milestone close |

A builder step (3.8–3.15m) builds against the contract of 3.2:
`*node-products*` in `tests/model/nodes.lisp` (each owned key → the
kinds its handler builds) and `docs/model.md`, "Node shapes"; a step
that builds something else changes its own rows of that table in the
same commit.  It is done only when its area's ratchet file
(`tests/model/undocumented-<area>.sexp`) is empty.  Fixtures come from
`build-fixture` / `make model`, which place nodes by the reader's line
(a vocabulary event reached through a setup macro has the span of that
macro's body, e.g. `(:begin :com)` at setup-aux.tex:843).

*Critic*: `full` runs `plan-critic` before the step; `none` does not (the
contract is the plan text, the docs it names and the tests).  *Review*:
the model of the `lisp-review` sub-agent.

## Critic

Whole-milestone critic (sonnet, 2026-11-27), all accepted:

1. Patches in sequence would shift each other's line numbers → M4:
   hunks in pristine coordinates, one edit set per file.
2. Keys and event kinds without an owner → 3.0's ownership table and its
   test; signatures named in 3.9.
3. Builders before text normalisation could not assert text → 3.12 moved
   to wave B, in every builder's *After*.
4. M4's patches shift fixtures and spans → 4.3 and 4.4 before wave C,
   line count preserved where possible, one session.
5. Shared files in a wave (References section, ratchet, generated
   files) → subsections, one ratchet per area, regenerate on merge.
6. Tiering → math split off (3.15m, *Critic* full), 3.10 *Critic* full,
   3.22 sonnet.  3.0 stays opus: it sets the layout every wave uses.
7. No place for patches M3 finds → 3.16p.
8. Sections without `\DefineSection` are unchecked; expected id
   collisions listed up front → 3.16.
