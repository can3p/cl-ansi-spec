# M4 — Patch tooling

Planned 2026-11-27, reviewed with M3 by one whole-milestone `plan-critic`
(see `docs/plan/m3.md`, "Critic").  Runs beside M3 in its waves A and B
(`docs/plan/m3.md`, "Parallel waves").

Goal: The patch files of `patches/` applied in order on top of `spec/tex/`, in Lisp,
strictly and reproducibly; every job reads the patched tree; the sources'
own errors that M2 pinned are fixed by patches, and the pins removed.

## Decisions taken at planning

- **Where the patched tree lives.**  In memory, behind the resolver
  (`docs/architecture.md`, "Sources": access goes through a pluggable
  resolver): a patched file is served under its own name with its patched
  text; spans point into that text.  The manifest names the patches, so
  pristine tree + patches reproduce every span.  `make patched` (4.2)
  writes the tree under `build/` for reading and diffing only.
- **Strict application, pristine coordinates.**  Unified diffs, paths
  relative to `spec/tex/`, every hunk's line numbers counted in the
  *pristine* file.  All hunks of all patches touching a file are merged
  into one edit set, checked, and applied in one pass from the bottom
  up, so no patch shifts another's lines.  Exact context: no fuzz, no
  offset.  A patch that does not apply is an error naming the patch, the
  hunk and the line.
- **Line count preserved where possible** (uncomment rather than add a
  line), so spans, `make events LINES=` and the builders' fixtures stay
  put; a patch that must add lines says so in its header.
- **Independence**, as `patches/README.md` requires, is checked, not
  trusted: each patch applies alone to the pristine tree, and no two
  patches' hunks (context included) overlap or touch, so any order gives
  the same tree.  Name order is only the manifest's order.
- **Header.**  The text before the first `--- ` line says why (erratum,
  typo, markup fix) and cites the lines; a test rejects an empty one and a
  name not `NNNN-short-description.patch`.
- **No patch to `vendor/`**, ever (its licence).
